# Wine installer and peripheral HID validation, 2026-11-13

The local Wine fork is retained. The source proof reconstructs the preceding source tree exactly by replacing only four files with their pre-change bytes. D3D9, D3D11, D3D12, DXGI, winemetal, FEX and the rest of Wine keep their installed payload bytes.

Wine's PowerShell placeholder returned success without evaluating commands. The tested NSIS installer interpreted its successful capability and process probes as an already-running application. Unsupported commands now fail, allowing the installer's normal tasklist fallback. Tasklist preserves full executable names and the complete filter operand, including spaces. A live process with the exact long spaced name was detected by the original NSIS command pipeline; absent and stopped processes were not. No process check is bypassed. PowerShell is still a placeholder, not an implementation of the shell.

The macOS IOHID backend previously discarded the attached receiver before it reached Windows HID enumeration. External feature-capable configuration interfaces now reach the existing raw HID stack. Ordinary mouse, keyboard and digitizer interfaces and built-in controls are excluded from this new path. For composite configuration descriptors, only report IDs whose input elements are entirely vendor-defined are forwarded. Mixed and protected input reports are suppressed; game controller behavior is retained.

On the attached B6A4:40C1 receiver, Windows enumerated the genuine feature interface, opened it for read/write access, and exchanged 41-byte feature reports. The manufacturer's unmodified application passed its VID/PID/name/report checks. Feature access alone initially left it disconnected; forwarding vendor input report 5 completed the response path. The recorded connection-status reply reported connected=1, battery=93 and chip=14. The actual manufacturer UI displayed the key assignment screen and 93% battery. No firmware update was performed.

The unmodified installer completed successfully in the isolated prefix. Native ARM64 and x86 unsupported PowerShell probes returned nonzero. The included Windows probe is diagnostic source; build with a MinGW compiler using -municode -luser32 -lsetupapi -lhid. Proprietary application binaries, ASAR files, firmware and full process environments are excluded. This validation covers the attached device, not every peripheral or proprietary Windows kernel driver.
